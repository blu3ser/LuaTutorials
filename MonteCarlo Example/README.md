# Monte Carlo Scenario Generation with Variations

This tutorial shows you how to create **different scenario variations** when using the Command Professional Edition Monte Carlo tool.

---

## Understanding Monte Carlo

The Command PE **Monte Carlo tool** runs the same scenario multiple times to generate statistical data. This is great for analyzing randomness and variability in outcomes - things like detection probabilities, weapon accuracy, and tactical uncertainty.

By design, the tool runs the **same scenario configuration** each time, which allows you to see how random factors affect outcomes.

**But what if you want to test different configurations in one analysis?** For example:
- Compare 2 bombers vs 4 bombers
- Test different weapon loadouts
- Evaluate the value of EW support

This tutorial shows you how to **extend the Monte Carlo tool** to test multiple configurations in a single batch.

---

## The Technique: Using an Event for Monte Carlo Variations

> **In this section:** Learn the core technique - using a timed event with a global ITERATION variable to track which run you're on and generate variations automatically.

### Part 1: Using an Event to Generate Variations

You create a **timed event** that runs at scenario start (1 second after scenario begins). This event contains a Lua script that generates the **variations** based on which iteration you're on.

**Important:** You can build your scenario however you want:
- **Option A:** Build a complete base scenario in the editor, then use the event to ADD variations
- **Option B:** Build a minimal scenario (just sides and timing), then use the event to build everything dynamically
- **Option C:** Mix of both - some elements in the editor, some generated by the event

**Why use an event?**
- The event script runs every scenario iteration at T+1
- You can put logic in the script to create different things each time
- Perfect for Monte Carlo where you want to test different configurations

### Part 2: The ITERATION Variable

Inside the event script, you use a **global variable called `ITERATION`** to track which run you're on:

```lua
-- This code is in the event script that runs at scenario start
if not ITERATION then
    ITERATION = 1              -- First run: start at 1
else
    ITERATION = ITERATION + 1  -- Next runs: add 1
end
```

**Key properties:**
- It's a **global variable** (not local)
- Starts at 1 on the first run
- **Automatically increments** each run (2, 3, 4...)
- **Persists throughout the entire Monte Carlo batch**

Think of it like a counter that keeps track of "which run am I on?" within a single Monte Carlo session.

### Part 3: Using ITERATION to Create Variations

Once you're tracking the iteration number, use it to decide what to build:

```lua
if ITERATION <= 10 then
    -- Runs 1-10: Create 2 bombers
    ScenEdit_AddUnit({side='BLUE', name='Bomber #1', ...})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #2', ...})

elseif ITERATION <= 20 then
    -- Runs 11-20: Create 4 bombers
    for i=1,4 do
        ScenEdit_AddUnit({side='BLUE', name='Bomber #'..i, ...})
    end
end
```

```
         │    ├─ Scenario loads (base elements)

         │    ├─ Generate Variation A (e.g., 2 bombers)
         │    └─ Scenario plays out → Results collected
         │
         ├──> ... (continues)
         │
         └──> Iteration 60
              ├─ Scenario loads (base elements)
              ├─ Event fires at T+1 second
              ├─ Script: ITERATION = 60
              ├─ Generate Variation F (e.g., full package)
              └─ Scenario plays out → Results collected

```

## ⚠️ CRITICAL: UI vs CommandCLI Difference

> **This is the most important thing to understand about ITERATION reset behavior.**

### Using CommandCLI (Automatic Reset ✅)
When you run Monte Carlo using CommandCLI, the Lua environment **resets automatically** between Monte Carlo batches:

```bash
CommandCLI.exe -mode mc -scenario scenario.scen -it 60
# ITERATION: 1 → 60

# Run again:
CommandCLI.exe -mode mc -scenario scenario.scen -it 60
# ITERATION: 1 → 60 (automatic reset!)
```

### Using the UI (Manual Reset Required ⚠️)
**When you run Monte Carlo from the Command PE UI, the Lua environment does NOT reset automatically.** The global variable persists!

**You MUST manually reset ITERATION before each new Monte Carlo batch:**

1. Open the Lua Console (`Ctrl+Shift+L` or Editor menu)
2. Type: `ITERATION = 0`
3. Press Enter
4. Now you can start your new Monte Carlo run

**What happens if you forget:**
```
First run:  ITERATION: 1 → 60   ✅ Correct
Second run: ITERATION: 61 → 120 ❌ WRONG! Your variation logic breaks!
With reset: ITERATION: 1 → 60   ✅ Correct
```

## The Two Scripts in This Example

> **In this section:** Understand what each script does and when to use it.

### [MonteCarlo Scenario Generation.lua](MonteCarlo%20Scenario%20Generation.lua)

**Purpose:** Creates the scenario framework with the event system embedded.

**When to run:** Execute this **once** in the scenario editor to generate your scenario file.

**What it does:**
1. Creates a blank scenario (database, sides, timing)
2. Embeds the entire [MonteCarloVariations.lua](MonteCarloVariations.lua) content into an event
3. Configures the event to trigger at T+1 second

**Key code pattern:**
```lua
local script = [=[
    -- Entire variation script goes here
]=]

local time = os.date('!%Y-%m-%dT%H:%M:%S', ScenEdit_CurrentTime()+1)
ScenEdit_SetTrigger({name="Start", type="time", mode='add', time=time})
ScenEdit_SetAction({name="WeaponFired", mode="add", type='LuaScript', ScriptText=script})
ScenEdit_SetEvent("LuaInit", {mode='add'})
ScenEdit_SetEventTrigger("LuaInit", {mode="add", name="Start"})
ScenEdit_SetEventAction("LuaInit", {mode="add", name="WeaponFired"})
```

> **Note:** The event triggers at T+1 second (not T+0) so you can load the scenario and make changes without triggering the full setup.

---

### [MonteCarloVariations.lua](MonteCarloVariations.lua)

**Purpose:** The actual variation logic that runs each iteration.

**This script is embedded into the event** and runs automatically every time the scenario starts.

**Key pattern:**
```lua
-- Track iteration
if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- Determine configuration based on iteration
local function generateMissionSettings(iterationNumber)
    local settings = {}
    local group = math.ceil(iterationNumber / 10)

    if group == 1 then
        settings.configuration = "Config A"
    elseif group == 2 then
        settings.configuration = "Config B"
    -- ... etc
    end

    return settings
end

local SETTINGS = generateMissionSettings(ITERATION)

-- Build scenario based on settings
-- ... create units, missions, etc.
```

Run [MonteCarlo Scenario Generation.lua](MonteCarlo%20Scenario%20Generation.lua) in the scenario editor:
- Customize the blank scenario setup (database, sides, timing)
- Modify the embedded variation script for your needs
- Save the scenario file

### 2. Configure Monte Carlo

In Command PE:
1. Open the Monte Carlo tool
2. Select your saved scenario
3. Set number of iterations (must match your script logic)
4. Configure output/logging options

### 3. Run

Start the Monte Carlo tool. For each iteration:
- Scenario starts → Event fires at T+1 second → ITERATION increments → Variations generated → Scenario plays out

### 4. Reset Between Batches (UI Only)

> ⚠️ **If using the UI:** Open Lua Console and type `ITERATION = 0` before starting a new Monte Carlo batch!

### 5. Analyze Results

Collect and compare results across the different configurations.

## Different Approaches

> **In this section:** Choose the approach that fits your workflow - from simple variations to full dynamic generation.

### Approach 1: Base Scenario + Variations (Recommended for Beginners)

Build your scenario in the editor with common elements, then use the event to add variations:

```lua
if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- Base scenario already has airbases and enemy defenses
-- Just add different bomber packages

if ITERATION <= 10 then
    -- Add 2 bombers
    ScenEdit_AddUnit({side='BLUE', name='Bomber #1', dbid=..., base='My Airbase'})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #2', dbid=..., base='My Airbase'})
elseif ITERATION <= 20 then
    -- Add 4 bombers
    for i=1,4 do
        ScenEdit_AddUnit({side='BLUE', name='Bomber #'..i, dbid=..., base='My Airbase'})
    end
end
```

**Pros:** Clean separation, easier to debug, can test base scenario independently

---

### Approach 2: Fully Dynamic (Like This Example)

Build everything in the event script:

```lua
if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- Build everything dynamically
local airbase = ScenEdit_AddUnit({side='BLUE', type='Facility', name='Airbase', ...})
-- ... create all enemy units
-- ... create bombers based on ITERATION
```

**Pros:** Complete control, everything in code, easy to version control and share

**Recommended for:** Experienced users who want full programmatic control

---

### Approach 3: Mixed (Recommended for Intermediate Users)

Some elements in editor, some generated dynamically:

```lua
if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- Modify existing elements
if ITERATION <= 10 then
    ScenEdit_SetDoctrine({side='BLUE'}, {weapon_control_status_air=0})
else
    ScenEdit_SetDoctrine({side='BLUE'}, {weapon_control_status_air=1})
end

-- Also add new units
ScenEdit_AddUnit({...})
```

## Key Concepts Summary

1. **Event for Variations** - Use an event to add/modify scenario elements based on ITERATION

2. **Global Variable Persistence** - ITERATION remembers its value across runs within a Monte Carlo batch

3. **⚠️ UI vs CommandCLI**:
   - **CommandCLI**: Automatically resets ITERATION between batches
   - **UI**: Does NOT reset - manually reset with `ITERATION = 0` in Lua Console

4. **Flexibility** - Build as much or as little in the editor as you want; the event handles variations

5. **Conditional Logic** - Use `if/then` statements to control what gets added/modified based on iteration

## Troubleshooting

### Problem: All iterations are the same
- Check that your variation script is embedded in the event correctly
- Verify the event triggers at scenario start (T+1 second)
- Add `print('ITERATION: '..ITERATION)` at the start of your script to see it in the log

### Problem: Iterations start at wrong number (61, 62, 63...)
- **This happens when using the UI** - the Lua environment doesn't reset between Monte Carlo batches
- You must manually reset ITERATION before starting a new batch
- Open Lua Console (`Ctrl+Shift+L`) and run: `ITERATION = 0`
- CommandCLI resets automatically, so this only affects UI usage

### Problem: Event doesn't fire
- Make sure the trigger time is set correctly (T+1 second)
- Check that the event, trigger, and action are all linked properly
- Verify the scenario isn't paused at start

### Problem: Script errors
- Test the variation script manually before embedding it
- Use simple logic first, then add complexity
- Check for syntax errors in the embedded script string

## Summary

**The Technique:**
1. Create your base scenario (as much or as little as you want)
2. Add an event that fires at T+1 second after scenario start
3. The event tracks ITERATION (global variable) and increments it each run
4. Use ITERATION to determine what variations to add/modify
5. The script dynamically adds or modifies scenario elements

**⚠️ Critical Difference:**
- **CommandCLI**: ITERATION resets automatically ✅
- **UI**: Must manually reset `ITERATION = 0` in Lua Console ⚠️

**Key Benefit:**
Transform the Monte Carlo tool from a simple repeater into a powerful comparison framework that can systematically test multiple configurations in a single batch.

**Key Insight:**
The event script is for **variations**, not necessarily for building the entire scenario from scratch. You have complete flexibility in how much you build in the editor vs. how much you generate dynamically.

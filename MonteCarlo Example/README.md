# Monte Carlo Scenario Generation with Variations

This tutorial shows you how to create **different scenario variations** when using the Command Professional Edition Monte Carlo tool.

## The Problem

The Command PE **Monte Carlo tool** runs the same scenario multiple times to generate statistical data. This is great for analyzing randomness (like detection probabilities, weapon accuracy, etc.), but by default it runs the **exact same scenario** every time.

**What if you want to test different configurations?** For example:
- Run iterations 1-10 with 2 bombers
- Run iterations 11-20 with 4 bombers
- Run iterations 21-30 with 2 bombers + EW support

This tutorial shows you how to do exactly that.

## The Solution: Using an Event for Monte Carlo Variations

The solution has two parts:

### Part 1: Using an Event to Generate Variations

You create a **timed event** that runs at scenario start (1 second after scenario begins). This event contains a Lua script that generates the **variations** based on which iteration you're on.

**Important:** You can build your scenario however you want:
- **Option A:** Build a complete base scenario in the editor, then use the event to ADD variations (extra units, different missions, etc.)
- **Option B:** Build a minimal scenario (just sides and timing), then use the event to build everything dynamically
- **Option C:** Mix of both - some elements in the editor, some generated by the event

**Why use an event?**
- The event script runs every time the scenario starts
- You can put logic in the script to create different things each time
- Perfect for Monte Carlo where you want to test different configurations

**How it works:**
1. Create your base scenario (as much or as little as you want)
2. Add a **timed event** that triggers 1 second after scenario start
3. This event executes a Lua script that adds/modifies things based on the iteration
4. Every time the Monte Carlo tool runs the scenario, this script runs and generates the variations

### Part 2: The ITERATION Variable

Inside the event script, you use a **global variable called `ITERATION`** to track which run you're on:

```lua
-- This code is in the event script that runs at scenario start
if not ITERATION then
    ITERATION = 1              -- First run: start at 1
else
    ITERATION = ITERATION + 1  -- Next runs: add 1
end
```

**Key properties of this variable:**
- It's a **global variable** (not local)
- Starts at 1 on the first run
- **Automatically increments** each run (2, 3, 4...)
- **Persists throughout the entire Monte Carlo batch**
- **Resets to 1 when you start a new Monte Carlo run**

Think of it like a counter that keeps track of "which run am I on?" within a single Monte Carlo session.

### Part 3: Using ITERATION to Create Variations

Once you're tracking the iteration number, use it to decide what to build:

```lua
-- Still inside the event script
print('Current iteration: ' .. ITERATION)

if ITERATION <= 10 then
    -- Runs 1-10: Create 2 bombers
    ScenEdit_AddUnit({side='BLUE', name='Bomber #1', ...})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #2', ...})

elseif ITERATION <= 20 then
    -- Runs 11-20: Create 4 bombers
    ScenEdit_AddUnit({side='BLUE', name='Bomber #1', ...})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #2', ...})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #3', ...})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #4', ...})

elseif ITERATION <= 30 then
    -- Runs 21-30: Create 2 bombers + EW support
    ScenEdit_AddUnit({side='BLUE', name='Bomber #1', ...})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #2', ...})
    ScenEdit_AddUnit({side='BLUE', name='EW Aircraft #1', ...})
end
```

## How the Complete System Works

Here's the full flow:

1. **Setup Phase** (done once):
   - Create your base scenario (build whatever elements you want in the editor)
   - Add an event with your variation script (or use [MonteCarlo Scenario Generation.lua](MonteCarlo%20Scenario%20Generation.lua))
   - The event will generate the variations based on ITERATION
   - Save the scenario file

2. **Monte Carlo Run** (automated):
   - Monte Carlo tool starts iteration 1
   - Scenario loads with your base elements
   - Event fires at T+1 second
   - Event script runs: `ITERATION = 1` (first run)
   - Script generates variations based on ITERATION = 1
   - Scenario plays out
   - Monte Carlo tool starts iteration 2
   - Scenario loads again with base elements
   - Event fires again at T+1 second
   - Event script runs: `ITERATION = 2` (increments!)
   - Script generates different variations based on ITERATION = 2
   - This continues for all iterations...

3. **Analysis Phase**:
   - Compare results across different configurations
   - Determine which approach performed best

## Understanding the Event Setup

### What's in the Event?

The event has three parts:

**Trigger:** Time-based, fires 1 second after scenario start
```lua
ScenEdit_SetTrigger({name="Start", type="time", mode='add', time='...'})
```

**Action:** Executes a Lua script
```lua
ScenEdit_SetAction({name="GameSetup", mode="add", type='LuaScript', ScriptText=script})
```

**Script:** Your variation logic (the entire [MonteCarloVariations.lua](MonteCarloVariations.lua) content)
```lua
local script = [=[
    if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

    -- Your scenario building code here
    -- This creates units, missions, etc. based on ITERATION
]=]
```

### Why 1 Second Delay?

The event triggers at T+1 second (not T+0) because:
- This way when you load the scenario you can make changes without triggering the full setup

## Important: When Does ITERATION Reset?

**Within a Single Monte Carlo Run:**
- ITERATION persists and increments (1, 2, 3... 60)
- The variable stays in the Lua global scope throughout the entire batch
- This is what allows the variations to work

**CRITICAL: Between Monte Carlo Runs**

The behavior depends on HOW you run Monte Carlo:

### Using CommandCLI (Automatic Reset)
When you run Monte Carlo using CommandCLI, the Lua environment resets automatically:
```
CommandCLI.exe /runmc scenario.scen 60
```
- First run: ITERATION goes from 1 to 60
- Run again: ITERATION automatically resets and goes from 1 to 60
- The environment is fresh each time

### Using the UI (Manual Reset Required)
**VERY IMPORTANT:** When you run Monte Carlo from the Command PE UI, the Lua environment does **NOT** reset automatically. The global variable persists!

**You MUST manually reset ITERATION before each new Monte Carlo run:**

Add this to your event script at the very beginning:
```lua
-- MANUAL RESET - Uncomment this line before starting a NEW Monte Carlo run via UI
-- ITERATION = nil

if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- Rest of your variation code...
```

**Workflow for UI:**
1. First Monte Carlo run:
   - Leave `ITERATION = nil` commented out
   - Run Monte Carlo → ITERATION: 1 to 60

2. Second Monte Carlo run:
   - **Uncomment** `ITERATION = nil` in the event script
   - Save the scenario
   - Run the scenario ONCE manually to reset the variable
   - **Comment out** `ITERATION = nil` again
   - Save the scenario
   - Run Monte Carlo → ITERATION: 1 to 60 (fresh start)

**Or simpler:** Just add `ITERATION = nil` before `if not ITERATION` and manually set it to nil when you need to reset.

**Examples:**

1. **CommandCLI (Automatic):**
   ```
   CommandCLI.exe /runmc scenario.scen 60  → ITERATION: 1-60
   CommandCLI.exe /runmc scenario.scen 60  → ITERATION: 1-60 (auto reset)
   ```

2. **UI (Manual Reset Required):**
   ```
   First run: ITERATION: 1-60
   Without reset: Second run starts at 61! (WRONG)
   With reset: Second run: 1-60 (CORRECT)
   ```

**Why this matters:** If you forget to reset when using the UI, your second Monte Carlo run will start with ITERATION = 61, 62, 63... which will break your variation logic!

## Different Approaches: Examples

### Approach 1: Base Scenario + Variations (Recommended)

Build a complete scenario in the editor with common elements:
- Airbases for both sides
- Enemy defenses (SAMs, radar)
- Target buildings
- Reference points, zones, etc.

Then use the event to add the variations:
```lua
if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- The base scenario already has airbases and enemy defenses
-- Just add different bomber packages based on iteration

if ITERATION <= 10 then
    -- Add 2 bombers with Harpoon
    ScenEdit_AddUnit({side='BLUE', name='Bomber #1', dbid=..., loadoutid=..., base='My Airbase'})
    ScenEdit_AddUnit({side='BLUE', name='Bomber #2', dbid=..., loadoutid=..., base='My Airbase'})
elseif ITERATION <= 20 then
    -- Add 4 bombers with JASSM
    for i=1,4 do
        ScenEdit_AddUnit({side='BLUE', name='Bomber #'..i, dbid=..., loadoutid=..., base='My Airbase'})
    end
end
```

**Pros:** Clean separation, easier to debug, can test the base scenario independently

### Approach 2: Fully Dynamic (Like This Example)

Create a minimal scenario (just sides and timing), then build everything in the event:
```lua
if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- Build everything - airbases, enemies, attackers, missions
local airbase = ScenEdit_AddUnit({side='BLUE', type='Facility', name='Airbase', ...})
-- ... create all enemy units
-- ... create bombers based on ITERATION
-- ... create missions and assign units
```

**Pros:** Complete control, everything in code, easy to version control and share

### Approach 3: Mixed (Maximum Flexibility)

Some elements in editor, some generated dynamically based on what changes:
```lua
if not ITERATION then ITERATION = 1 else ITERATION = ITERATION + 1 end

-- Modify existing scenario elements
if ITERATION <= 10 then
    ScenEdit_SetDoctrine({side='BLUE'}, {weapon_state='hold'})
else
    ScenEdit_SetDoctrine({side='BLUE'}, {weapon_state='free'})
end

-- Also add new units
ScenEdit_AddUnit({...})
```

**Pros:** Use the best of both worlds

## Key Concepts for Non-Technical Users

1. **Event for Variations**: Use an event to add/modify scenario elements, not necessarily to build everything from scratch

2. **Global Variable Persistence**: The `ITERATION` variable remembers its value across runs within the same Monte Carlo batch

3. **UI vs CommandCLI Difference**:
   - **CommandCLI**: Automatically resets ITERATION between runs
   - **UI**: Does NOT reset - you must manually reset ITERATION = nil before each new Monte Carlo run

4. **Automatic Execution**: Everything happens automatically once you start the Monte Carlo tool

5. **Base + Variations**: You can have a base scenario (built in editor) plus variations (generated by event script)

6. **Conditional Logic**: Simple `if/then` statements control what gets added/modified based on iteration number

7. **Flexibility**: Use the event for as much or as little as you need - just the variations, or the entire scenario

## Troubleshooting

**Problem:** All iterations are the same
- Check that your variation script is embedded in the event correctly
- Verify the event is set to trigger at scenario start
- Add `print('ITERATION: '..ITERATION)` at the start of your script to see it in the log

**Problem:** Iterations start at wrong number (61, 62, 63...)
- **This happens when using the UI** - the Lua environment doesn't reset between Monte Carlo runs
- You must manually reset ITERATION before starting a new run
- Add `ITERATION = nil` at the start of your event script, run the scenario once to execute it, then comment it out
- CommandCLI resets automatically, so this only affects UI usage

**Problem:** Event doesn't fire
- Make sure the trigger time is set correctly (T+1 second)
- Check that the event, trigger, and action are all linked properly
- Verify the scenario isn't paused at start

**Problem:** Script errors
- Test the variation script manually before embedding it
- Use simple logic first, then add complexity
- Check for syntax errors in the embedded script string

## Summary

**The technique:**
1. Create your base scenario (as much or as little as you want)
2. Add an event that fires at T+1 second after scenario start
3. The event executes a script that tracks ITERATION (global variable)
4. ITERATION automatically increments each run and persists within the Monte Carlo batch
5. Use ITERATION to determine what variations to add/modify
6. The script dynamically adds or modifies scenario elements based on ITERATION

**CRITICAL DIFFERENCE:**
- **CommandCLI**: ITERATION resets automatically between Monte Carlo runs
- **UI**: ITERATION does NOT reset - you must manually set `ITERATION = nil` before starting a new Monte Carlo run

**Key benefit:** Transform the Monte Carlo tool from a simple repeater into a powerful comparison framework that can systematically test multiple configurations in a single batch.

**Key insight:** The event script is for **variations**, not necessarily for building the entire scenario from scratch. You have complete flexibility in how much you build in the editor vs. how much you generate dynamically.
